# External research: ComfyUI 2D Character Pipeline

**Draft research.** Source inspection only. The target is [mor-o/comfyui-2d-character-pipeline at `9fee239216b8fb5a841401644a4ef629496e563c`][upstream]. The experiments below are proposals. This study did not run either experiment, install dependencies from the target, or load model weights.

## Conclusion

Use W4's separation of candidate generation and pixel preservation. Test one masked repair on an existing part, then copy original RGBA bytes outside an explicit edit area. Keep the source PNGs and compare the other 17 file hashes. Use the existing C0.5 checks to decide if the candidate saves manual work.

W1 supplies a useful geometric cue for a whole character reference. It has no mechanism to place or label 18 detached parts. Test transfer only if the current sheet generator can use a reference image without changing the rest of the recipe. Keep the shared C0.5 skeleton, Spine animations, and deterministic extraction. The source gives no reason to adopt the video pipeline, general-purpose MCP server, or neural segmentation as a required stage.

## Architecture and evidence

The external project generates a series of complete images for each motion. It also generates cosmetic overlays for those same frames. W1 is an optional posed keyframe helper. W2 turns a keyframe into a short video. W3 removes the background, reduces the color to luma for tinting, and packs the frames in a horizontal strip. W4 edits a region of the base video. W5 isolates the cosmetic in each edited frame and packs a matching strip. Installation into the consumer asset directory and registration of the strips are manual steps. [Overview][overview], [W2 design][w2-doc], [W2 graph][w2].

AIGG starts with the Modular Sheet Prompt v2.5 and expects 18 detached body parts. It extracts independent PNGs, maps joints to the shared C0.5 candidate skeleton, and exports through Spine. The owner reports real-character `idle` and `wave`, a Spine Editor export, and browser playback. The remaining blocker is geometry at wrists, knees, and ankles. AIGG reuses motion across characters. The external project recomputes art for each motion and cosmetic. A frame strip has no AIGG slot, pivot, attachment rectangle, or hidden joint overlap. [AIGG roadmap](../ROADMAP.md#pipeline-v2--mvp-core), [V2-3 assembly](../proposals/V2_3_SKELETON_ASSEMBLY_SPIKE.md).

**Evidence.** Shipped graphs and drivers establish wiring and defaults. The author reports runs on one chibi character and includes idle, walking, and in-air sample strips. W1's documented checks are visual checks of idle keyframes. W4's two-pass and W5 cosmetic examples are author reports. The public tree has no automated tests for rig compatibility, protected RGBA bytes, or multiple characters. Proposed depth variants and future runtime behavior have separate, weaker evidence. [Project README][readme], [samples][samples], [W1 status][w1-doc], [W4 status][w4-doc], [W5 status][w5-doc].

## W1: Pose control

W1 reads an OpenPose body PNG as a separate image, not a list of joints passed to the sampler. `tools/render_openpose.py` reads the first person's COCO-18 points and draws colored links and joints on black. Zero-confidence points are omitted. The shipped graph stretches the source image to 512 × 512 (7 → 8). The source supplies appearance to `TextEncodeQwenImageEditPlus` (9–10) and the initial VAE latent (11). Geometry comes from the pose PNG (17) and the InstantX model (15). `ControlNetApplyAdvanced` (18) attaches the pose hint to both conditionings over the full denoising range. The graph uses Qwen-Image-Edit-2509 with a Lightning LoRA (2), four Euler steps, CFG 1, and denoise 1 (12). `VAEDecode` (13) and `SaveImage` (14) output one complete figure. There is no protected-pixel mask. [Renderer][pose], [W1 graph][w1], [Qwen encoder source][qwen-encode].

The graph sets `openpose` on `SetUnionControlNetType` (16). In the inspected ComfyUI implementation, this node stores a `control_type` argument. The InstantX Qwen ControlNet accepts extra arguments but does not read this mode flag. Its forward pass uses the image hint to supply model residuals. The historical ComfyUI revision used by the author is unknown. The driver replaces the graph's frontal prompt, seed, and strength 1.3 with a side-facing prompt, seed 30123, and strength 1.6. Both default prompts remove appearance features for the target's base figure. AIGG needs a prompt that keeps the clothed design and the C0.5 three-quarter view. The sparse wrist/ankle depth renderer is separate. No depth node or driver input connects it to W1. [W1 `build_workflow` and defaults][w1-driver], [depth renderer][depth], [ComfyUI Union setter][union-set], [InstantX model forward][union-model].

The source image and prompt can preserve the design approximately while the pose changes. The graph can also redraw clothing, silhouette, hands, and face. A 2D joint drawing supplies limb endpoints, with no torso yaw, foot direction, reliable depth order, slot identity, or overlap silhouette. It can suggest a neutral pose but cannot enforce it. A detached limb crop lacks the full-person context used in the published examples. There is no evidence that moving the links into 18 boxes would preserve the sheet layout or map image left/right to AIGG near/far. Use C0.5 labels, independent landmarks, and the attachment rectangles to judge those properties. [Qwen model card][qwen], [InstantX model card][instantx], [C0.5](../proposals/C05_REFERENCE_MANNEQUIN.md).

AIGG already has an OpenPose renderer and whole-figure evidence on a different model stack. In C1, pose guidance reduced mean joint error from 13.3% to 1.3% for one seed. The torso and foot orientation still failed, and only five of eight limb segments met their length bounds. In C2, the orientation gate failed in all six images, with and without depth. These results support measuring transfer to detached parts before giving W1 further GPU time. [C1](../proposals/C1_GEOMETRY_EVALUATION.md), [C2](../proposals/C2_FAILURE_ANALYSIS.md).

## W4: Repair and pixel preservation

**Pass 1.** The driver stages the base video and one matching still with the target cosmetic. Use of a no-cosmetic reference and a pixel diff appears in the overview but is absent from the shipped path. SAM3 segments the cosmetic on the still (7, mask output 1). The enhancer (10) smooths, fills holes, and dilates the mask. With the graph's zero blur and thresholded smoothing, this is effectively a hard expanded region. The same still conditions Wan VACE (18). A split sampler (22 and 29) starts with stronger prompt guidance and then uses CFG 1 with the CausVid LoRA. The driver can change the number of steps and mask size. [W4 `stage_inputs` and `build_pass1`][w4-driver], [pass 1 graph][w4-p1], [enhancer implementation][enhancer].

**Pass 2.** SAM3 extracts a tighter per-frame mask from the decoded pass 1 video (4–6 → 9–10). VACE edits the original base again with the still reference and the new mask. It does not refine pass 1 pixels in place. The driver can reuse a prior pass 1 file. The checked-in run targets eyes, uses nine frames, and skips pass 2. Its dilation defaults are 25 and 10 px. The hair templates use 15 and 3 px. The author uses pass 2 when the broad mask allows a halo or bleed. Sweeps still missed some thin hair strands. The still reference is guidance, and two passes do not give an exact shape. [W4 `build_pass2` and `main`][w4-driver], [pass 2 graph][w4-p2], [W4 design and results][w4-doc].

**Pixel guarantee.** Both graphs decode the candidate (25). `ImageCompositeMasked` (26) blends it over the decoded, resized base (3), using the enhanced mask at zero offset. With zero mask coverage, the compositor returns the base RGB value. A soft mask permits changes wherever its coverage is positive. The compositor repeats a singleton mask across frames, but the inspected `WanVaceToVideo` instead pads short mask batches with ones. The documentation's static mask description holds for the final composite. It does not establish the same constraint during VACE sampling. The graph then encodes H.264 from RGB through YUV420P (27–28). The preserved values are pre-encode RGB values, with no guarantee of equality after MP4 readback. W4 stores mask previews, not repaired RGBA parts. [Pass 1 graph][w4-p1], [pass 2 graph][w4-p2], [mask composite source][composite], [VACE mask padding][vace], [video encoder][video-save].

For a still part, one candidate and a deterministic PNG composite are sufficient to test the hypothesis. Choose an edit area in part coordinates. Define the candidate's silhouette alpha separately so it can add missing material in allowed transparent pixels or remove a bridge. Where the edit mask is zero, copy original straight RGBA bytes directly, including RGB under zero alpha. Feather only inside the recorded edit area. Save lossless PNG at the original dimensions without rescaling protected pixels. Copy the unrelated PNGs without re-encoding and record input, mask, candidate, and output hashes. A seed helps reproduce a proposal. The saved candidate and mask reproduce the composite even if inference changes.

| Defect                       | What a single-part trial can do                                                                                                                                                         |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Incorrect hand               | Edit fingers or the silhouette using the intact wrist and the reference as context. Protect the wrist anchor and side identity.                                                         |
| Missing joint overlap        | Extend the parent part into allowed transparent space. Check the child pivot and coverage when the joint bends.                                                                         |
| Sleeve or trouser transition | Use the neighboring part as read-only context. A seam that needs changes to both parts exceeds this trial.                                                                              |
| Fused foot and shin          | Remove a bridge or replace one invalid part only if the other required part is already valid. If a required PNG is missing or both parts need edits, mark the one-part trial as failed. |
| Replace one part             | Use the part's rectangle as the maximum edit area. The other 17 files remain byte-identical. A complete replacement still needs the same joint, alpha, and style checks.                |

## W3 and W5: Segmentation and alpha

W3 uses `BiRefNetRMBG` (10), preset `BiRefNet_toonout`, for foreground matting of the whole character. It uses only the predicted mask from that node. The original RGB frames follow a separate scale and luma path (20, 26–28). The mask is scaled and inverted before `JoinImageWithAlpha` (21–25). Setting `refine_foreground=true` does not affect the output because the graph discards the refined RGB output. The driver adds frame slices (100 onward), a stitch chain (200 onward), and save node 300. The author reports an idle example with background and shadow removal. [W3 graph][w3], [W3 `build_workflow` and `main`][w3-driver], [W3 results][w3-doc].

W5 uses text-prompted SAM3 (10) with merged detections per frame, followed by smoothing, hole fill, and optional dilation (11). The driver can select color and patch the prompt, frame count, and mask parameters. Its defaults target eyes on idle. The guide describes hair on walking. The join (25) uses pixels from the edited video. No node compares them with the base video. Therefore the mask is a semantic guess at cosmetic coverage, with potential bleed or missing detail. The author reports a hair example and found SAM3 unreliable for the iris alone. The optional green-key script extracts a deliberately colored iris by thresholding channels. It can select any matching green pixel and is specific to that staged input. [W5 graph][w5], [W5 `build_workflow`][w5-driver], [W5 results][w5-doc], [iris `build_iris_sheet`][iris].

For separated RGBA parts, `sheet-check` already reports bounds and connected alpha components at a fixed threshold. `sheet-extract` copies the region bytes. These operations are exact, inexpensive, and independent of model versions. A component that crosses a transparent gap can flag a fusion. `sheet-check` rejects foreground outside all regions, but it does not test semantic fusions. A fusion wholly inside one region can look like one valid component, and one valid part can have multiple components. Neither a component count nor a SAM3 prediction establishes slot identity or anatomical validity. [Control README](../../packages/control/README.md#modular-sheet-v2-1), [real-sheet assessment](../proposals/V2_1_REAL_SHEET_ASSESSMENT.md).

Consider BiRefNet only if an opaque or contaminated background still blocks extraction after deterministic alpha cleanup. Consider SAM3 for human-reviewed proposals for hair, clothing, or an edit area when alpha cannot identify the intended region. Neither can supply hidden material, reliable anti-aliased alpha for every detail, or an authoritative mask for a pixel preservation check. The inspected current RMBG schema requires a `model_name` input missing from the W4 and W5 graphs. [RMBG SAM3 source][sam-node], [RMBG BiRefNet source][biref-node].

## Execution and reproducibility

The target stores API graphs as maps from node IDs to `class_type`, `inputs`, and `_meta`. W1 and W2 identify nodes by type and title. W4 and W5 patch fixed IDs. Their Python drivers submit `POST /prompt` and poll `/history/<prompt_id>` for a terminal entry. The drivers report some server-side errors and use overall polling limits. Polling errors can be retried, but there is no durable submission record, explicit per-request bound on submission and history polling, or automatic reconciliation after an ambiguous POST. Seed retries are manual. W1 gives runs numbered directories. W2 finds the largest directory suffix and then selects a posed image by modification time. Drivers copy files into known server directories on the same host. W4 uses output node 28 to identify the pass video. The W2 quick start implies a source PNG in `input/` is sufficient. The shipped driver instead requires a posed PNG under a versioned output directory. W2's `FPS` is printed by the driver, while node 17 retains the graph value. [Harness guide][harness], [W1 driver][w1-driver], [W2 `build_workflow` and `main`][w2-driver], [W4 `wait_for` and `output_files`][w4-driver].

The AIGG experiment C runner already validates graph input names and options against `/object_info`, pins model hashes, and uses explicit outputs. It records submission intent and the prompt ID to avoid submitting twice. It fetches a bounded PNG with `/view`, checks dimensions, and records the output hash. If a new backend is approved, reuse these patterns in the existing TypeScript tooling. Keep one narrow, optional adapter and let the rest of the pipeline consume ordinary PNGs. Reject implicit selection by modification time. The artokun MCP exposes process, queue, workflow, and model management. The Python drivers do not depend on it. Those extra commands would duplicate authority outside the repair task. [AIGG `runner.ts`](../../packages/control/src/runner.ts), [ComfyUI routes][routes], [harness MCP section][harness].

The downloader's `MODEL_LIST` maps repositories and file names to local folders. `download_one` follows default Hub revisions, trusts any existing pathname, and lacks a digest check. An exception can be logged without failing the final run. The script can load a token from a local file and prints a token prefix. Its `--w4` flag selects only the VACE and LoRA entries. UMT5 and VAE are in the W2 group, and segmentation is delegated to on-demand downloads. Use AIGG's existing revision and SHA-256 checks. Pin application, nodes, runtime dependencies, graph, and model files. Record the prompt, seeds, input and mask digests, device, runtime versions, timings, and terminal status. [Downloader `MODEL_LIST`, `download_one`, `load_token`, `run`][download], [model registry](../MODEL_LICENSES.md).

## Two bounded experiments

Both proposals require owner approval before runs, downloads, installation, use of character art on a service, or spending. The thresholds below are trial gates. They do not amend the rig contract. Store all candidate assets and run records outside Git.

### A. Skeleton-guided reference for direct modular generation

- **Hypothesis.** A C0.5 pose hint improves independent part geometry when used through the current sheet generator's reference input. A better whole figure alone does not support this claim.
- **Inputs and tools.** Freeze one authorized clothed design, the C0.5 candidate contract and OpenPose image, Prompt v2.5, and three paired seeds. Use the six W1 files and a reviewed ComfyUI setup. Use AIGG's pose renderer and fixed three-quarter setup pose. Use the same aspect-preserving padding for the reference and pose coordinates. Require a current sheet generator that accepts an optional reference without other recipe changes. Keep model, prompt, resolution, and sheet seeds fixed across sheet conditions.
- **Smallest comparison.** Render three pairs of posed reference PNGs. Use the same source and W1-style edit settings in each pair. Change only pose strength from zero to a predeclared nonzero value. Check orientation and geometry before generating sheets. If at least two guided references pass, make three matched groups of sheets. Each group has a text-only baseline, the unguided edited reference, and the guided reference. The extra reference condition separates pose guidance from the effect of adding any reference.
- **Outputs and validation.** Save up to six references and nine RGBA sheets with layout descriptors, annotations, extracted parts, overlays, and assembly reports. Blind the scorer to the condition. Use `overlay --marks` for whole-figure measurements. Use `sheet-check`, `sheet-extract`, and `sheet-assemble` for sheet evidence. Check `spine-validate` and browser `idle` and `wave` for one passing guided candidate through the existing owner workflow.
- **Acceptance.** For the reference gate, require the C0.5 mean and maximum joint error limits of 1.5% and 2.5% of body height, segment ratios of 0.95–1.05, and correct torso, feet, and near/far orientation. Mark hidden joints as unmeasurable and do not count them as passes. For sheet transfer, at least two guided sheets must have all 18 separate, correctly labeled parts, valid scales and child-joint residuals, and correct pivots and overlap in setup and motion. Count seam gaps at the wrist, knee, and ankle. Require lower paired median non-anchor joint error than both baselines and no new gap or side swap. Measure residuals independently of the joints used to place the parts. Report error in pixels and state the denominator for percentages. The V2-3 assembly check uses canvas height, while `overlay` uses body height. Review leg seams at bent checks if demo motions leave them static.
- **Cost and stop.** Estimate 30–60 minutes of 48 GB host time for the W1 work and checks after setup. The sheet generator's time and per-image price are separate and unknown. Approve a cap before starting. Stop on a failed reference gate, unsupported reference input, invalid condition, or the run cap. If the guided sheets fail, keep the text-only route and record whether the failure was pose, identity, layout, alpha, or overlap. One character and three seeds give a screening result.

### B. Masked repair of one existing forearm

- **Hypothesis.** A bounded still edit can restore the missing wrist overlap on `forearm_near` with less human time than a manual correction. W4 does not establish this for detached parts. Confirm that the defect is missing painted coverage. If joint placement alone fixes it, use the current calibration work instead.
- **Inputs and tools.** Use an owner-selected snapshot of the existing 18 parts, its descriptor and baseline joint marks, and the frozen C0.5 candidate contract. Mark a small binary edit area that includes allowed transparent space at the wrist. Use the matching hand and surrounding art as read-only context. Propose the five-file Qwen-Image-Edit-2509 stack from W1 without InstantX. Provide a padded crop and indicated repair region. Treat Qwen as a still candidate generator, because the shipped graph has no native inpaint mask. Use a manually reviewed candidate matte and a deterministic CPU composite. Use existing image tools for the trial.
- **Outputs and validation.** Save the original crop, edit mask, candidate RGB or RGBA, matte, final PNG of the same dimensions, and a report with hashes, prompts, seeds, and versions. Run `sheet-check` and `sheet-extract` on a lossless sheet derivative with a matching descriptor. Compare all 18 extracted parts to the baseline. Assemble through `sheet-assemble` and inspect the wrist in setup, bent views, and browser `idle` and `wave`. Use `spine-validate` for a candidate that passes the offline checks.
- **Acceptance.** Require zero unequal RGBA pixels outside the binary edit area after PNG readback, including pixels with alpha zero. Require 17 original PNG file SHA-256 matches. Keep slot, dimensions, joint anchors, draw order, and near/far identity. Require the painted parent to cover the existing contract target at the wrist, with no new gap, halo, bridge, or clipped cuff in the reviewed poses. Measure the change in missing parent alpha pixels inside the contract's 24 px radius at `hand_near`. Require no missing coverage on the approved target and run the assembly's near-arm check. Have a human review anatomy, line art, and color. Record active time for mask, matte, and cleanup and compare with a timed manual correction of the same defect.
- **Cost and stop.** Use one crop, one edit pass per candidate, and at most three predeclared seeds. Estimate 15–30 minutes of host time after setup, plus human marking and review. Dollar cost is approved host time times the applicable rate, plus storage and transfer if billed. Main risks are crop reinterpretation, alpha work taking longer than hand editing, or failure to fill the overlap. Stop at the first accepted candidate, a change to protected pixels or unrelated files, or the cap. If none passes with lower manual time, keep manual correction.

## Next action

After the owner completes or takes a stable snapshot of V2-R2 joint calibration, select one paint defect for B. Before any inference, approve the part and mask, measurement sheet, exact model files and node revisions, private endpoint, and run and spend caps. Keep A deferred until an authorized reference-capable sheet generator is available. A failed or negative trial is useful evidence to keep the existing process.
