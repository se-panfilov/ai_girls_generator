# Component inventory and deferred cleanup plan

**Draft.** This inventory classifies the existing components by pipeline generation (D35). The classifications and the cleanup plan are **proposed**. They change no code. Each removal needs a separate owner decision and a separate pull request.
Sources: [Pipeline v1](PIPELINE_V1.md), [the Pipeline v2 ADR](proposals/PIPELINE_V2_ADR.md), the package READMEs, and the import graph of the source code at the time of writing.

## Classification

| Class          | Meaning                                                                         |
| -------------- | ------------------------------------------------------------------------------- |
| `shared`       | Pipeline v1 and Pipeline v2 need it, or it does not depend on the input method. |
| `v2-candidate` | Pipeline v2 can reuse it, but it needs changes or validation first.             |
| `v1-only`      | Specific to the concept decomposition workflow.                                 |
| `unknown`      | Not enough evidence to classify.                                                |

A package is not `v1-only` only because some of its commands are. The classification is for each component.

| `@aigg/seethrough-bundle` | `v1-only`                                                                                                 | Every command serves one owner-run See-through decomposition.                                       |

| `@aigg/rig-runtime`       | `shared`                                                                                                  | Reads `character.json`, atlases, and the shared skeleton. It has no See-through input.              |
| `@aigg/viewer`            | `shared`                                                                                                  | Reads a Spine export only.                                                                          |

## Dependencies between packages

- No package has a runtime dependency on another workspace package.
- `@aigg/factory` starts the built CLIs of `@aigg/control` and `@aigg/viewer` as subprocesses (`packages/factory/src/tools.ts`). Its tests build `@aigg/control` and run the real `assemble-body` on a synthetic body. They also read the C0.5 candidate contract fixture of `@aigg/control`.
- The `@aigg/control` tests run the `parseCharacter` function of `@aigg/rig-runtime` from source (`packages/control/test/rig-runtime/parse-character.mjs`) to check the `character.json` of `assemble-body` and `template`.
- `@aigg/viewer` does not use `@aigg/rig-runtime` (documented exception in the MVP-C report).

## Deferred cleanup plan

**Proposed. Not executed.** No item below is authorized. Each item needs a separate owner decision and a separate pull request. Do not start an item before the Pipeline v2 MVP core (steps 1 to 5 of the roadmap) has passed, unless the owner decides otherwise.

### General rules for any removal

- **Proof of no use.** Before a removal, show that nothing uses the component: a search of the import graph, a search of the documentation and the factory stage table, and a green `npm run check` after the removal on the branch.
- **Archived workflows.** The evidence archives name tool versions. The Git history keeps the code of each version. A removal does not change the archives.
- **Rollback.** A removal is one commit or one pull request with no other change. Recovery is a revert of that change. The owner can also ask for a tag on the last commit that has the component (tags need explicit authorization).
- **Version.** A removal of a CLI command is a breaking change of the package. Bump the major version (or the minor version while the package is `0.x`) and say so in the pull request.
